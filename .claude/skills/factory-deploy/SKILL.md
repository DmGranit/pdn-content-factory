# Развёртывание контент-завода

Ты разворачиваешь этот репозиторий на машине пользователя до состояния «работает на автомате».
Веди по шагам, после каждого показывай результат проверки. Секреты пользователь вписывает
СВОЕЙ рукой — ты их не читаешь и не печатаешь.

## Шаг 1 — окружение

Проверь и покажи пользователю:

```bat
python --version     &REM нужен 3.10+
claude --version     &REM Claude Code CLI — двигатель AI-этапа
pip show flask       &REM для пульта; нет -> pip install flask
```

Нет Claude CLI → поставить по официальной инструкции (claude.com/claude-code) и войти в аккаунт.

## Шаг 2 — секреты (рука пользователя)

1. `copy .env.example .env`
2. Попроси пользователя открыть `.env` в блокноте и вписать:
   - `TELEGRAM_BOT_TOKEN` — токен бота (@BotFather), бот должен быть **админом канала**;
   - `TELEGRAM_CHANNEL` — свой канал;
   - `OPENAI_API_KEY` — только если нужны картинки (без него завод собирает черновики без картинок).
3. Сам файл НЕ открывай. Проверь только факт существования: `if exist .env echo ok`.

## Шаг 3 — тест рельсов (без AI, ключей и сети)

```bat
python tests\test_schedule.py
set CF_DRAFT_MODE=stub
python content_factory_run.py
```

Проверка: тесты дают «15 PASS, 0 FAIL»; появился `_STATUS.md` с вердиктом «готово» и
файл-заявка `_DRAFT_REQUEST_*.txt` в `drafts/`. Нет — разбери ошибку до перехода дальше.

## Шаг 4 — боевой прогон одного черновика

```bat
run_scheduled.bat
```

Идёт ~10 минут: субагент ищет повестку, проверяет факты, кладёт JSON + ПРЕДПРОСМОТР в `drafts/`.
Проверка: в `drafts/` появился новый `.json`, в `_STATUS.md` — «готово» с его именем.

## Шаг 5 — пульт апрува (человек-гейт)

```bat
run_console.bat
```

Открой пользователю <http://127.0.0.1:5055>. Он видит черновик, картинку и ближайшие слоты,
и решает: **«Одобрить»** — пост уезжает в `approved/` и выйдет в канал в ближайший слот;
**«Опубликовать сейчас»** — срочный выход мимо расписания; **«Отклонить»** — в `rejected/`.
Напомни: в канал попадает ТОЛЬКО одобренное им — так и задумано, это не баг.

## Шаг 6 — сетка публикаций

Открой пользователю `schedule.json` и объясни по-простому: каждая строка — это день недели,
время (**по Москве**, не по времени его компьютера), рубрика и угол подачи. Рубрика не
диктует тему — тема всегда самая свежая, рубрика задаёт ракурс. Файл правится блокнотом,
код менять не нужно. Там же `approval_ttl_days` — сколько дней действует одобрение.

## Шаг 7 — автоматика (две задачи)

```bat
schtasks /Create /TN PDN_ContentFactory_Draft   /SC DAILY  /ST 09:00 /TR "<путь>\run_scheduled.bat"
schtasks /Create /TN PDN_ContentFactory_Deliver /SC HOURLY            /TR "<путь>\run_deliver.bat"
```

Первая раз в сутки делает черновик, вторая раз в час проверяет, не наступил ли слот
(почасовой опрос — чтобы пост вышел, даже если ПК в момент слота был выключен).

Проверка: `schtasks /Query /TN PDN_ContentFactory_Deliver /V /FO LIST` и `python deliver.py --dry` —
покажет, что доставщик сделал бы сейчас, ничего не публикуя.
Итог любого прогона — в `_STATUS.md`, полная история — в `_audit.md`.

## Шаг 8 — лента сайта (необязательно)

Если у пользователя есть репозиторий лендинга с `news.json` — впиши в `.env` строку
`CF_SITE_REPO=<путь к репо>`. После каждой публикации завод добавит пункт в ленту и
**остановится**: коммит и push на боевой сайт пользователь делает сам. Проверка —
`python news_writer.py --status`. Не задана переменная — лента просто не ведётся, это не ошибка.

## Аварийный тормоз

Создать файл `STOP` в корне — плановые прогоны выходят, ничего не делая. Убрать файл — завод снова жив.

## Чего НЕ делать

- Не публиковать в канал самому и не «тестировать» публикатор без явной просьбы пользователя.
- Не вписывать и не читать значения ключей; не коммитить `.env` (он в .gitignore).
- Не менять редполитику (`docs/EDITORIAL_POLICY.md`) — это правила канала, их меняет владелец.
- Не коммитить и не пушить репозиторий лендинга — завод только готовит `news.json`.
- Не писать кириллицу и пути в `.bat`-файлы: консоль Windows читает их в OEM-кодировке и
  ломает строки. Всё машинно-локальное — в `.env`.
